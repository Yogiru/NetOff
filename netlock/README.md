# NetLock

**Облегчённая альтернатива [NetOff](../README.md) в том же репозитории** —
временный заглушитель интернета **без туннеля, без службы,
без обязательных прав администратора**. Одна команда `nl run` — и
внешний трафик отрубается на заданное время; локальная сеть и адреса из
allowlist продолжают работать.

## Как работает

Три движка, выбор по правам (или флагом):

- **`wfp`** — Windows Filtering Platform: блок-фильтры на восьми уровнях
  (ALE connect/recv-accept + входящие/исходящие IP-пакеты, IPv4 и IPv6)
  в собственном сабслое с максимальным приоритетом. Не обходится
  маршрутами и не выключается другими правилами файрвола. Сессия
  динамическая — при смерти процесса фильтры исчезают сами.
  Требует админа.
- **`fw`** — запасной privileged-путь: block-правила Windows Firewall
  через COM (`INetFwPolicy2`) для систем, где вырезаны
  `fwpmu.dll`/`fwpuclnt.dll`. Правила персистентны — снимаются при
  выходе или `nl restore`.
- **`proxy`** — без прав вообще: системный прокси пользователя (HKCU)
  направляется на локальный deny-листенер `127.0.0.1:17887`, который
  честно отвечает `403` (мёртвый порт заставлял бы клиентов падать
  в прямое соединение). Allowlist уходит в `ProxyOverride` — разрешённые
  адреса идут напрямую.

`engine = auto` (дефолт): под админом `wfp` с авто-фолбэком на `fw`,
без прав — `proxy`.

## Быстрый старт

```bat
nl run 60          :: глушить минуту, потом само отпустит
nl run             :: до Ctrl+C
nl run 300 -min    :: свернуть: отсчёт в заголовке, прогресс на таскбаре
nl run 300 -hide   :: вообще без окна

nl run -wfp        :: принудительно WFP (админ)
nl run -fw         :: принудительно COM-firewall (админ)
nl run -proxy      :: принудительно proxy (работает и без прав)

nl status          :: права, доступные движки, конфиг, активный блок
nl fwplan          :: показать план fw-правил без применения
nl restore         :: вернуть прокси из backup + снять fw-правила
```

Минимальная длительность блока — 30 секунд.

## netlock.ini

```ini
[main]
seconds = 0          ; 0 = до Ctrl+C; минимум 30
engine = auto        ; auto | wfp | fw | proxy

[allow]              ; разрешённые адреса — по строке
192.168.0.0/16       ; CIDR (wfp/fw) и wildcard для proxy
10.0.0.0/8
*.lan                ; wildcard/имена хостов — только proxy-режим
```

## Честное ограничение

`proxy`-режим ловит только proxy-aware трафик (браузеры,
WinHTTP/WinINet-приложения, большинство программ). Raw-сокеты,
ICMP/ping, торренты и приложения, игнорирующие системный прокси,
проходят мимо — гарантированный блок без прав администратора в Windows
невозможен в принципе. Для 100% — `wfp`/`fw` под админом.

## Отказоустойчивость

- **wfp**: крах процесса = фильтры снимаются сами (dynamic session).
- **fw**: правила переживают крах, но подметаются при следующем
  `run` или `nl restore`; `status` предупреждает об остатках.
- **proxy**: крах оставляет блок активным; исходные настройки лежат в
  `netlock-backup.ini` — `nl restore` возвращает их (или следующий
  запуск подхватит автоматически).

## Требования

Windows Vista и новее, x64. Права администратора — только для
`wfp`/`fw` движков.

См. также [NetOff](../) — вариант с туннелем wintun и службой
для постоянного контроля.
