# NetOff — справка пользователя

Интернет-заглушка для Windows: роняет весь IP-трафик через
wintun-адаптер, оставляя живыми только сети из белого списка
(локалка, WG-эндпоинты и т.п.). Консольная утилита + Windows-служба
в одном exe, плюс отдельный GUI-пульт.

> Программа требует права администратора (`requireAdministrator`
> в манифесте) — нужны для служб, маршрутов и адаптера.

- **exe**: `bin\netoff.exe` (консоль/служба), `bin\netoff-gui.exe` (пульт)
- **dll**: `bin\wintun.dll` — обязательно рядом с `netoff.exe`
- **конфиг**: `netoff.ini` рядом с exe
- **лог службы**: `netoff-service.log` рядом с exe

> ⚠️ Двойной клик по `netoff.exe` — окно мелькнёт и закроется: это
> консольная утилита, без параметров она показывает справку и выходит.
> Запускать из консоли (cmd/Terminal, **от администратора**).

---

## 1. Как это работает (коротко)

Блокировка двухслойная:

1. **WFP-стена** (Windows Filtering Platform — то же, что kill-switch
   у VPN-клиентов): фильтры «запретить всё» на 8 слоях ядра
   (v4+v6, исходящие+входящие, на уровне потоков и пакетов). Не
   обходится ни маршрутами, ни другим адаптером, ни уже открытыми
   соединениями новых потоков.
   Разрешены только: loopback, сети из `[allow]`, локальный
   мультикаст/link-local, DHCP.
2. **Wintun-чёрная дыра**: адаптер **NetOff** + маршруты `0.0.0.0/1`,
   `128.0.0.0/1` и IPv6-аналоги заворачивают трафик в цикл-сток —
   работает как резерв и показывает счётчик дропнутых пакетов.
3. Сети из `[allow]` получают явные маршруты через реальный шлюз —
   локалка и разрешённые хосты продолжают работать.
4. И WFP-фильтры, и маршруты **самоснимаются при смерти процесса**
   (динамическая WFP-сессия + конечный lifetime маршрутов ~3 мин).

**Блокировка — минимум 30 секунд.** `seconds = 0` — до ручной остановки.

> Чего не покрывает: трафик вне IP-стека (сырые пакеты через
> Npcap-подобные драйверы, PPPoE) — то же ограничение у штатного
> kill-switch WireGuard.

## 2. Консольные команды

```
netoff run [сек] [-min|-hide]   блок в foreground: N сек. или до Ctrl+C
netoff install [тип]            установить службу (auto|demand|disabled)
netoff uninstall                удалить службу
netoff start                    запустить службу (берёт ini)
netoff stop                     остановить службу
netoff starttype <тип>          тип запуска: auto|demand|disabled
netoff status                   состояние службы, тип запуска, allow
netoff cleanup                  удалить сироты wintun-адаптеров NetOff
netoff help                     справка (также /?, -h, --help, /h)
netoff version                  версия (также ver, -v, --version)
```

### Флаги окна

- `-min` (`--min`, `/min`) — свернуть консоль в панель задач.
- `-hide` (`--hide`, `/hide`) — полностью отцепиться от консоли
  (`FreeConsole`): ни окна, ни кнопки. Остановить такой экземпляр —
  `taskkill`, `netoff stop` (если это служба) или конец таймера.

Флаги можно ставить в любой позиции: `netoff -min run 60` тоже работает.

> Если запустить `run -min` из уже открытой консоли — свернётся окно
> самой консоли (оно общее). Для `-min` запускайте отдельным ярлыком.

### Прогресс в панели задач

При `run` с лимитом заголовок окна (он же подсказка кнопки в панели
задач и Alt+Tab) обновляется каждую секунду:

- `NetOff — заглушен, осталось 4:37`
- `NetOff — заглушен (без лимита), дропнуто 128`
- `NetOff — блок снят`

Плюс на кнопке рисуется прогресс-бар (как при скачивании в браузере):
зелёный — при таймере, «бегущий» — при бессрочном блоке. По окончании
полоска снимается. При `-hide` прогресса нет — окна нет.

## 3. netoff.ini

```ini
[main]
; длительность блока в СЕКУНДАХ для службы и `netoff run` (мин. 30)
; 0 = до остановки вручную
seconds = 0

[allow]
; сети/хосты, которые НЕ блокируются — CIDR или голый IPv4 (=/32)
192.168.0.0/16
10.0.0.0/8
8.35.211.2          ; WG-эндпоинт — туннель продолжит жить
```

- `;` и `#` — комментарии.
- Allowlist нужен, чтобы во время блока оставались живыми локальная
  сеть и, например, внешний WireGuard-эндпоинт — иначе туннель тоже
  ляжет.

## 4. GUI-пульт (`netoff-gui.exe`)

Компактный диалог: статус службы вверху (иконка + текст), кнопки
управления, редактор `netoff.ini`.

- **Установить службу / Удалить** — install/uninstall.
- **Запустить / Остановить** — start/stop службы.
- Таймер: снятая галочка «до Остановить» + секунды = блок на N секунд.
- Тип запуска: auto / demand / disabled.
- **Сохранить netoff.ini** — пишет секции `[main]`/`[allow]`.

### Таймерный запуск из GUI

Если установлен конечный таймер, «Запустить»:

1. стартует службу;
2. сворачивает окно в панель задач;
3. показывает отсчёт в заголовке (`осталось M:SS`) и зелёный
   прогресс-бар на кнопке — как у консольной версии.

По истечении таймера или при остановке службы заголовок и кнопка
возвращаются к обычному виду, окно разворачивается.

> Отсчёт GUI знает только о блоках, запущенных из него самого —
> у службы запущенной из консоли дедлайн наружу не отдаётся.

### Иконка статуса

| Иконка | Состояние |
|---|---|
| синий «i» | служба не установлена |
| красный крест | RUNNING — интернет заглушен |
| жёлтый треугольник | start/stop pending |
| щит | stopped — интернет доступен |

## 5. Чистка адаптеров

`netoff cleanup` удаляет все wintun-адаптеры с именем `NetOff`
(служба при этом должна быть остановлена — команда откажет, если
она запущена). Печатает по каждому найденному адаптеру результат
или код ошибки.

Адаптеры-сироты могли накопиться от старых версий: раньше каждый
запуск создавал новый адаптер вместо переиспользования.

Запасные варианты (админская консоль):

```
pnputil /remove-device "SWD\Wintun\..."
```

или Диспетчер устройств → Сетевые адаптеры → NetOff → Удалить
(«Вид → Показать скрытые устройства», если не видно).

## 6. Вопросы-ответы

**Запускаю из консоли — «The requested operation requires
elevation».** Нужна консоль от администратора.

**`netoff.exe` мелькает и пропадает.** Это норма для двойного клика —
консольная утилита. Запуск из cmd: `netoff help`.

**Блок кончился, а интернет не вернулся.** Подождите до ~3 минут
(догорает lifetime маршрутов) или `netstop NetOff` / `netoff stop`.

**Во время блока пропала локалка.** Добавьте её в `[allow]`
(`192.168.0.0/16` уже есть по умолчанию).

**Накопились адаптеры NetOff 2..35.** `netoff cleanup` — чинится
в сетевых подключениях.

**Служба не стартует.** Смотрите `netoff-service.log` рядом с exe.
